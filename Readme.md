Служба доставки беспилотниками — вариант 38


Сборка и запуск
Нужны Linux или WSL, компилятор GCC/Clang, make.

make
./fly_simulator                         # консольное меню
./fly_simulator --auto                  # запустить пример без меню
./fly_simulator --auto --delay 100      # пауза 100 мс между тактами
./fly_simulator --auto --scenario scenarios/small.txt
make test                               # 10 проверок
В меню: 1 — симуляция, 2 — карта, 3 — информация об объектах, 4 — выход. Ctrl+C останавливает симуляцию.

Как устроена программа
Файл	Что делает
main.c	Меню, запуск и вывод исходных данных
scenario.c	Чтение исходных данных из файла
map.c	Сетка карты и поиск пути BFS
plane.c	Проверка веса, движение и расход энергии
order.c	Состояния заказа
dispatcher.c	Поиск подходящего беспилотника
station.c	Зарядка и ограничение числа мест
weather.c	Смена погоды
simulation.c	Модельное время, потоки, маршруты и события
Файлы .h находятся в inc/, реализации — в src/.

Потоки. Один такт разделён на четыре последовательных этапа: обработка заказов, диспетчер, беспилотники, зарядные станции. Для каждого участника соответствующего этапа создаётся поток pthread_create; прежде чем перейти дальше, главный поток ждёт его завершения через pthread_join.

Маршрут. Кратчайший путь по клеткам в четырёх направлениях находится простым BFS; клетки # запрещены. Время движения — один такт на клетку, расход энергии фиксированный.

Диспетчер. Для очередного заказа выбирается свободный беспилотник, который может поднять груз, успеет до предельного срока при хорошей погоде и имеет энергию на путь до склада → до получателя → до зарядной станции. Среди подходящих выбирается тот, кто сможет доставить раньше. При плохой погоде полёты приостанавливаются, после улучшения погоды маршрут пересчитывается.

Зарядка. Станции имеют ограниченное число мест. Если все места заняты, прилетевший аппарат ждёт на клетке станции и пробует занять место на следующем такте. Энергия пополняется с заданной скоростью. Отдельной очереди с приоритетами нет.

Завершение. Заказы становятся DELIVERED только после прибытия в точку. Невыполнимые до срока заказы переходят в FAILED. Программа завершает работу после обработки заказов и завершения активных маршрутов, при достижении лимита времени или по Ctrl+C.

Формат сценария
Одна команда на строку. Координаты: строка столбец, нумерация с нуля. Строки после # — комментарии.

size 5 5
warehouse 0 0
block 2 1
station 1 4 4 2 5
# station ID row col places charge_per_tick
# drone ID row col load_capacity max_energy initial_energy energy_per_step
drone 1 0 0 5 60 60 2
# order ID row col weight arrival_time deadline
order 1 4 0 3 0 20
weather_interval 0
max_time 30
weather_interval 0 отключает смену погоды, иначе каждые N тактов погода переключается между хорошей и плохой. max_time 0 — работать до обработки всех заказов (либо Ctrl+C).

В комплекте три сценария: demo.txt, small.txt и deadline.txt. Все параметры можно изменить без перекомпиляции.
